## 5. Проблема: не работает копирование в буфер (проброс на ПК)

**Пользователь:** у тебя в чате не работает копирование в буфер обмена с
пробросом на ПК с которого я подключаюсь

**Пользователь (доп.):** cntrl+shift+c в этом терминале также не работает

### Ошибочная гипотеза (потом скорректирована)

Сначала был найден истёкший сертификат `alexserv.taila28720.ts.net`
(Let's Encrypt, истёк 16.08.2026) в NPM. Это оказалось **неверным** диагнозом —
тот сертификат относился к старому/неиспользуемому хосту.

### Корректный разбор

**Пользователь:** Ты бредишь. Я хожу через code.myaiteach.ru/4443

**Реальный путь:**

```
Chrome (Windows) → https://code.myaiteach.ru:4443 (NPM)
    → proxy_pass https://alexserv.taila28720.ts.net:18443 (Tailscale Serve)
    → code-server (127.0.0.1:8080)
```

Сертификаты **действительны**:
- `code.myaiteach.ru` — Let's Encrypt, выпущен 24.09.2026, истекает 23.12.2026.
- Tailscale Serve — продлевается автоматически.

### Причины проблемы clipboard (две отдельные)

1. **Копирование из чата (сервер → ПК).** Qwen Code на сервере пишет в буфер
   через **OSC 52**. Встроенный терминал code-server **не ретранслирует OSC 52**
   в буфер браузера — известное ограничение code-server.

2. **Ctrl+Shift+C.** Подключение идёт через **Chrome на Windows** (видно в
   access-логе NPM). В Chrome `Ctrl+Shift+C` зарезервировано за **Inspect Element**
   (DevTools), поэтому вместо копирования ничего не происходит.

### Решения

- В браузере: выделить текст → **правая кнопка мыши → Copy**.
- Включить автокопирование: `"terminal.integrated.copyOnSelection": true`.
- Для чата/TUI: подключаться по **SSH** из нормального терминала
  (`ssh alex@alexserv.taila28720.ts.net`) — там OSC 52 и буфер работают нативно.
- Обходной путь: сохранять ответы в файл и копировать из редактора code-server.
