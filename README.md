# Решения задач из хэндбука по C++

Учебный репозиторий с решениями задач и небольшими экспериментами по C++. Программы охватывают базовый синтаксис, условия, циклы, строки, контейнеры, алгоритмы, числовые типы, классы и перегрузку операторов.

Условия части задач: [хэндбук Яндекса в Яндекс Контесте](https://new.contest.yandex.ru/contests/42155/problems).

Большинство `.cpp`-файлов в корне — отдельные консольные программы со своей функцией `main`, которые собираются по одной. Исключение: [`tikTakToe.cpp`](./tikTakToe.cpp) содержит класс игры, а [`ticTakToeMain.cpp`](./ticTakToeMain.cpp) — программу для его запуска. [`main.cpp`](./main.cpp) содержит пустой `main`, [`treeFunctions.cpp`](./treeFunctions.cpp) — заготовку с подключением заголовков без `main`.

В репозитории есть несколько вариантов одних и тех же решений: например, n-граммы подсчитываются через `std::multiset` в [`nGramma.cpp`](./nGramma.cpp) и через `std::map` в [`nGramma1.cpp`](./nGramma1.cpp). Функция [`Unique`](./unique.cpp) повторяет основную семантику `std::unique`: удаляет только соседние повторы и возвращает новую логическую границу диапазона.

Некоторые имена файлов (`doublicateVector.cpp`, `pringContainer.cpp`, `unird_count_freqs.cpp`) сохранены в исходном виде, поэтому при сборке используйте точное имя из таблицы ниже.

### Пример: top-k самых частых слов

В [`frequencyWords.cpp`](./frequencyWords.cpp) сначала подсчитывается частота каждого слова, затем слова выводятся по убыванию частоты, а при равенстве частот — по алфавиту. Текущая версия добавляет в очередь все `U` уникальных слов. Можно ограничить очередь `k` лучшими кандидатами: для каждого слова добавлять его, пока очередь не заполнится, а затем заменять худший элемент только тогда, когда найдено слово получше.

Для этого компаратор должен описывать желаемый порядок «лучше раньше». Например, запись с большей частотой лучше, а при равной частоте лучше лексикографически меньшее слово:

```cpp
using WordFrequency = std::pair<std::size_t, std::string>; // частота, слово

struct Better {
    bool operator()(const WordFrequency& lhs,
                    const WordFrequency& rhs) const {
        if (lhs.first != rhs.first) {
            return lhs.first > rhs.first;
        }
        return lhs.second < rhs.second;
    }
};

std::priority_queue<WordFrequency,
                    std::vector<WordFrequency>,
                    Better> candidates;

for (const auto& [word, count] : freqs) {
    WordFrequency candidate{count, word};
    if (candidates.size() < k) {
        candidates.push(candidate);
    } else if (Better{}(candidate, candidates.top())) {
        candidates.pop();
        candidates.push(candidate);
    }
}
```

У `std::priority_queue` вершина — максимальный элемент согласно её компаратору. Поэтому с `Better` на вершине оказывается худший из сохранённых кандидатов: его удобно удалить, когда найден кандидат лучше. Тот же компаратор можно использовать для итоговой сортировки — компаратор очереди и компаратор `std::sort` не конфликтуют:

```cpp
std::vector<WordFrequency> result;
while (!candidates.empty()) {
    result.push_back(candidates.top());
    candidates.pop();
}
std::sort(result.begin(), result.end(), Better{});
```

Обработка `U` уникальных слов с такой очередью занимает `O(U log k)`, а очередь хранит не более `k` элементов вместо `U`. Подсчёт частот всё равно хранит все уникальные слова в `freqs`, поэтому общая память остаётся `O(U)`; уменьшается именно дополнительная память очереди. Если собирать результат извлечением из очереди без `std::sort`, порядок будет от худшего к лучшему, и вектор нужно развернуть.

### Пример: разбор строки на токены

В [`nextToken.cpp`](./nextToken.cpp) функция `NextToken` при каждом вызове возвращает очередной токен до символа-разделителя. Она возвращает `true`, пока есть токены, и меняет переданный `std::string_view`, сдвигая его начало за найденный разделитель. Например, для строки `Hello world and good bye` и разделителя-пробела последовательность токенов будет такой:

```text
Hello
world
and
good
bye
```

`std::string_view::find` возвращает индекс найденного разделителя или `std::string_view::npos`, если разделителя больше нет. Токены и остаток строки — представления исходных символов, поэтому копирования текста нет. Исходные данные должны оставаться действительными, пока используются эти представления. Если разделители стоят рядом или в начале строки, функция выдаёт пустой токен; по условию задачи строка не заканчивается разделителем.

### Пример: дерево директорий

Программа [`fileSystem.cpp`](./fileSystem.cpp) получает пути к файлам до конца стандартного ввода. Например:

```text
/home/guest/homework/A/main.cpp
/home/guest/homework/B/readme.txt
```

Она выделяет все непустые директории, удаляет повторы с помощью `std::set` и печатает пути в лексикографическом порядке:

```text
/
/home/
/home/guest/
/home/guest/homework/
/home/guest/homework/A/
/home/guest/homework/B/
```

При поиске слешей справа налево важно отдельно обрабатывать позицию `0` до вычисления `pos - 1`. Тип `std::string::size_type` беззнаковый: если вычесть единицу из нуля, получится `std::string::npos`, а `rfind` начнёт новый поиск с конца строки. Это приводит к зацикливанию вместо завершения обхода.

### Класс Tree: дерево строковых ключей

В [`tree.cpp`](./tree.cpp) каждый `Node` хранит непосредственных потомков в `std::map<std::string, Node>`. Вектор строк задаёт путь от корня: `{"home", "alex", "docs"}` означает последовательность вложенных узлов. Это структура в памяти; обращения к настоящей файловой системе нет.

- `Insert` создаёт недостающие узлы пути.
- `Has` проверяет существование всего пути, не меняя дерево.
- `Delete` доходит до родителя последнего узла и удаляет этого потомка вместе с поддеревом. Если путь отсутствует, ничего не происходит.

По условию передаваемые пути непустые. Текущий демонстрационный `main` добавляет путь `home → alex → docs` и печатает только имена непосредственных детей корня — `home`. Метод `GetNode()` возвращает копию корня.

### Класс TicTacToe: крестики-нолики

Класс в [`tikTakToe.cpp`](./tikTakToe.cpp) хранит поле `N × N`, заполненное нулями. Значения `1` и `2` обозначают фишки игроков. `Set(i, j)` ставит фишку текущего игрока, переключает игрока и возвращает признак победы: не менее `K` одинаковых фишек подряд по строке, столбцу или одной из диагоналей через сделанный ход. `operator()` читает клетку, `GetCurrentPlayer()` возвращает номер игрока, который ходит следующим.

Для запуска в Linux:

```bash
mkdir -p build
g++ -std=c++17 -g -O0 -Wall -Wextra -Wpedantic ticTakToeMain.cpp -o build/ticTacToe
./build/ticTacToe
```

[`ticTakToeMain.cpp`](./ticTakToeMain.cpp) сначала читает `N K`, затем пары координат `строка столбец` до EOF. Индексы начинаются с нуля и должны быть меньше `N`. Например:

```text

0 0
1 0
0 1
1 1
0 2
```

Ожидаемый вывод по текущему коду:

```text
Player #1 wins!
XXX
OO.
...
```

Для печати итогового поля завершите ввод: в Linux — <kbd>Ctrl</kbd>+<kbd>D</kbd> на пустой строке. Программа продолжает читать ходы и после победы. Координаты и занятость клетки в `Set` не проверяются, поэтому подавайте допустимые ходы в свободные клетки.

В текущей версии оператор `<<` печатает непосредственно в `std::cout`, хотя принимает поток `out`; вывод в другой поток требует исправления оператора. Демонстрационные `main` в `tree.cpp` и `ticTakToeMain.cpp` завершаются с кодом `1`, даже при обычном завершении.

### Класс Date: два способа хранения

В [`classDate.cpp`](./classDate.cpp) дата хранится в трёх полях `int`: день, месяц и год. В [`classDateIDigital.cpp`](./classDateIDigital.cpp) используется одно поле `int` — число дней от 1 января 1970 года. В обоих вариантах доступны константные геттеры `GetDay`, `GetMonth`, `GetYear`, сложение и вычитание количества дней, а также разность двух дат в днях.

Диапазон задачи — от 1 января 1970 года до 31 декабря 2099 года. Некорректные аргументы конструктора дают дату 1 января 1970 года. Для арифметики предполагается, что результат остаётся в указанном диапазоне.

В представлении одним числом 1 января 1970 года соответствует `0`, а 31 декабря 2099 года — `47481`. Сложение и вычитание меняют число дней в копии объекта, а разность дат вычисляется вычитанием двух чисел. Геттеры восстанавливают компоненты через общую функцию, возвращающую временную структуру `DateParts`; дополнительных полей хранения в объекте нет.

Обратное преобразование в `classDateIDigital.cpp` использует мартовский год и четырёхлетние блоки по 1461 дню. Оно рассчитано на диапазон этой задачи: внутри него високосные годы следуют каждые четыре года, включая 2000 год. В `classDate.cpp` обратное преобразование использует 400-летние периоды по 146097 дней.

Пример использования любого из двух вариантов класса:

```cpp
Date date(28, 2, 2024);
Date next = date + 1;

std::cout << next.GetDay() << ' '
          << next.GetMonth() << ' '
          << next.GetYear() << '\n';  // 29 2 2024

std::cout << Date(1, 3, 2024) - date << '\n';  // 2
```

### Класс Rational и встроенные проверки

В [`rational.cpp`](./rational.cpp) класс хранит числитель и знаменатель в двух полях `int`. Конструктор сокращает дробь через `std::gcd` и переносит знак в числитель, чтобы знаменатель был положительным. По умолчанию создаётся `0/1`; один аргумент задаёт целое число со знаменателем `1`.

Реализованы бинарные `+`, `-`, `*`, `/`, унарные `+` и `-`, составные присваивания `+=`, `-=`, `*=`, `/=`, сравнения `==` и `!=`. Для арифметики с `int` справа используется преобразующий конструктор, а слева — отдельные свободные перегрузки. При умножении и делении множители сокращаются до вычисления произведений.

```cpp
Rational half(1, 2);
Rational third(1, 3);
Rational sum = half + third;

std::cout << sum.Numerator() << '/'
          << sum.Denominator() << '\n';  // 5/6

Rational mixed = 2 * half + third * 3;  // 2/1
```

Нулевой знаменатель и деление на нулевую дробь проверяются через `assert`; эти проверки отключаются при определении `NDEBUG`. Перекрёстное сокращение уменьшает промежуточные произведения, но реализация остаётся ограничена диапазоном `int`.

Текущий `main` не читает ввод: он выполняет проверки арифметики с `int` слева, знаков, нуля, смешанных выражений и сохранности исходных объектов через макрос `CHECK`. Если все проверки проходят, программа печатает `all ok` и возвращает `0`. При несовпадении она выводит выражение и строку в `stderr`, печатает число ошибок и возвращает ненулевой код.

Для самостоятельного запуска этих проверок в Linux:

```bash
mkdir -p build
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic rational.cpp -o build/rational
./build/rational
```

Для отправки решения задачи на класс в проверяющую систему отделяйте реализацию от демонстрационного `main` и локальных проверок в соответствии с форматом задания.

### Работа в VS Code и code-server

В репозитории настроены сборка и отладка активного `.cpp`-файла под Linux. Для основной конфигурации отладки требуется расширение CodeLLDB. Компилятор `g++` должен быть доступен в окружении code-server; адаптер отладки предоставляет CodeLLDB.

Откройте нужный `.cpp`-файл и используйте одну из команд:

- <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>B</kbd> — собрать активный файл;
- <kbd>F5</kbd> с конфигурацией `C++17: build, debug and use terminal input (LLDB)` — собрать активный файл и запустить с отладчиком LLDB.

Задача сборки из [`.vscode/tasks.json`](./.vscode/tasks.json) вызывает `g++ -std=c++17 -g -O0 -Wall -Wextra -Wpedantic` для текущего файла и записывает исполняемый файл в `.vscode/build/program`. Основная конфигурация [`.vscode/launch.json`](./.vscode/launch.json) запускает его во встроенном терминале, поэтому входные данные можно вводить там же. Для игры перед сборкой или нажатием F5 откройте `ticTakToeMain.cpp`: файл класса `tikTakToe.cpp` не содержит `main` и отдельно как программа не собирается.

Данные для `std::cin` вводите во вкладке «Терминал». Сообщение CodeLLDB `Console is in 'commands' mode, prefix expressions with '?'.` относится к Debug Console и не является ошибкой: эта консоль принимает команды отладчика, а выражения вводятся с префиксом `?`, например `? currentPlayer`, при остановке внутри метода класса.

Если `preLaunchTask` завершилась с кодом `1`, смотрите сообщения компилятора или компоновщика выше в терминале. Например, `undefined reference` к методу может означать, что метод объявлен, но его реализация отсутствует.

В `launch.json` также сохранена конфигурация `C/C++ Runner: Debug Session`: она использует тип `gdb` расширения Native Debug (`webfreak.debug`) и исполняемый файл `build/Debug/outDebug`, который нужно собрать заранее. Поля `target` и `gdbpath` соответствуют формату этого расширения. Эта конфигурация не выполняет задачу сборки активного файла; для интерактивного ввода используйте основную конфигурацию CodeLLDB.
